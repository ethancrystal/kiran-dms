# Documentation audit, findings register (Phase 1)

**Audit date:** 2026-11-19 (PKT). **Base:** `main` at `d4b47ca`. **Mode:** read-only. This register was written and committed before any document was changed, so the record shows the audit came first. Dispositions are recorded in [07-final-consistency-report.md](07-final-consistency-report.md), not here.

**Scope:** every Markdown file tracked in git (148 files, `docs/log/archive.md` excluded because it is frozen), plus the CI workflows, `supabase/tests/`, `apps/web/e2e*` and the migration list as implementation evidence. Supabase was not queried. Earlier evidence reused: the read-only gap audit of the same commit (77 tables, 348 functions, 197 client-callable, 175 used by the UI).

**Method:** a script extracted every requirement ID defined in doc 03 (164), every reference to a requirement, decision (`D-`), open question (`OQ-`), blocker (`B-`), assumption (`A-`) and hard rule (`H-`) ID, every relative Markdown link and every back-quoted repository path, and every requirement ID cited in a test file. The numbered documents, SPEC.md, CONTEXT-MAP.md, AGENTS.md and CLAUDE.md were then read for conflicts by hand.

**Type tags** (first word of the Issue): `[DUPLICATE]`, `[CONFLICT]`, `[OUTDATED]`, `[WORKFLOW]` (incomplete workflow or missing scenario), `[NO-AC]` (missing acceptance criteria), `[ROLE]` (missing role or permission definition), `[SECURITY]` (missing security or data-integrity requirement), `[REFERENCE]` (broken reference or inconsistent ID), `[STATUS]` (planned, implemented and verified differ), `[GOVERNANCE]` (instruction files).

**Decision Required:** "yes" means only MJ can settle it; the options are listed and none is chosen here. "yes (open)" means the question is already open as a B-, OQ- or pending item. "no" means the fix needs no business decision.
