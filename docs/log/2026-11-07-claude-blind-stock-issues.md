**What / why:** The rep confirms a stock issue or return with its own count, which is meant to be blind. The rep's page read public.stock_issue directly under RLS, so the office's quantities (lines) reached the browser and the second count could be copied. New app.my_pending_issues() gives a rep on an approved phone the pending issues of its own bag with the SKU ids to count and never a quantity (id, direction, note, time, sku_ids). The rep select policy on public.stock_issue is dropped, so the table is readable by the office only. The page reads the function and builds its count fields from the SKU ids. This is a tightening of an existing control, not a loosening.
**Test changes that follow from the design:** the RLS matrix row for stock_issue now expects repA and repB to see no rows (it expected their own bag's rows); the verifier allowlist of functions callable by authenticated gains my_pending_issues. Both are the intended new state, named here because they edit existing expectations. The test file was renamed from blind-stock-issues.test.ts to rep-blind-stock-issues.test.ts so it sorts after inventory.test.ts (which creates the shared bag fixtures) and avoids a unique-constraint collision.
**Security addition (2026-11-09, Antigravity):** A second quantity-leakage path was identified: app.rep_confirm_stock_issue returned the entire stock_issue row (including lines) even when a rep submitted a disputed count. A rep could intentionally submit a wrong count to learn the office quantities via the JSON response. The migration 20261107010000 now also replaces app.rep_confirm_stock_issue with an identical function that zeroes v.lines before returning, so the response never contains office quantities on any code path (confirmed and disputed). A new test in rep-blind-stock-issues.test.ts asserts that a disputed confirmation returns lines = [] and does not contain the office's figure. db:test cannot run from WSL (only Windows native rolldown+embedded-postgres binaries are installed); CI is the evidence. typecheck also not re-run locally.
